# Start Here - Codex Bootcamp

A Codex Bootcamp by [AIsandboxlab.com](http://AIsandboxlab.com).

By the end, you will have researched a market, analyzed customer data, written a PRD, built a working web page, and optionally published it. You do it by talking to Codex in plain English. No coding background needed.

You play the founding Product Manager at a fictional startup called **Signal**. Every mission moves the same product forward.

## What you need

1. **One Codex interface ready.** Follow [INSTALL.md](INSTALL.md) if needed.
2. **This folder on your computer.** Follow [GET-THIS-PROJECT.md](GET-THIS-PROJECT.md) if needed.
3. **About 15-20 minutes per mission.** Your progress is saved in `PROGRESS.md`.

## Start in your preferred interface

The course itself is identical across all three routes. Only the way you open the folder changes.

| Interface | Open the course | Start the mentor |
|---|---|---|
| **Desktop app** | Add or open this folder as a Codex project | Start a task in the project and type `begin` |
| **Codex CLI** | In a terminal, run `cd `, drag this folder onto the window, then press Enter | Run `codex`, then type `begin` |
| **IDE extension** | Use **File > Open Folder**, then open the Codex panel | Start a local chat and type `begin` |

Codex reads the root `AGENTS.md` when it starts in this project. That file turns it into your course mentor. If Codex answers like a generic assistant, confirm that you opened the whole bootcamp folder, not an individual file, and start a fresh task or session.

## Codex basics worth knowing

**Talk normally.** Describe the outcome you want. Name the source file, destination file, and required sections when that matters.

**Point to files.** You can type a path such as `data/interview-call.txt`. In interfaces that offer file mentions, select the file from the composer. Open files in an IDE also provide useful context.

**Review before accepting.** Codex may show a proposed edit, diff, or permission request. Read what it wants to change. Ask "what will this do?" whenever an action is unclear.

**Stop and redirect.** Use the visible stop control, or `Esc` where supported, if Codex heads in the wrong direction. Then clarify the goal and continue.

**Plan bigger changes first.** Say "give me options before changing files" or "make a plan first." If your interface offers Plan mode, you can use it, but the plain-English request works everywhere.

**Interfaces differ slightly.** The desktop app is strongest for projects and visual review. The CLI is direct and dependable. The IDE keeps files and chat side by side. Mission instructions use shared prompts and call out interface-specific controls only when needed.

## Use AI responsibly

- **You own the result.** Codex drafts and computes quickly, but it can be wrong. Review numbers, quotes, conclusions, and final files.
- **Keep secrets out of prompts and commits.** Never paste passwords, API keys, or real customer personal data. Review permission requests before approving them.
- **Treat external actions as real actions.** Publishing, installing software, connecting an account, or sending data outside the project should happen only when you intend it.

## The four course shortcuts

| Type this | What happens |
|---|---|
| `begin` | Start or reopen the current mission |
| `hint` | Get one small nudge; repeat for a larger one |
| `check my work` | Ask the mentor to inspect the required artifact |
| `next` | Mark a completed mission done and move forward |

You can also say `I'm stuck`, `explain that`, or `what mission am I on?`.
